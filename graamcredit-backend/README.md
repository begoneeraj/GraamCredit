# GraamCredit Backend

FastAPI + SQLite backend for the GraamCredit AI-powered rural microloan eligibility checker.

## Quick Start

### 1. Navigate to the backend folder
```bash
cd graamcredit-backend
```

### 2. Create and activate a virtual environment
```bash
# Create
python -m venv venv

# Activate — Windows
venv\Scripts\activate

# Activate — Mac/Linux
source venv/bin/activate
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

### 4. Configure environment variables
```bash
# Copy the template
cp .env.example .env   # Mac/Linux
copy .env.example .env  # Windows
```
Open `.env` and fill in your SMTP credentials and secret key.  
The `DATABASE_URL` default (`sqlite:///./graamcredit.db`) works out of the box.

### 5. Train the ML model
```bash
python ml/train.py
```
This generates 1000 synthetic rows, trains LogisticRegression and RandomForest,
prints accuracy/AUC-ROC metrics, and saves the better model to `ml/model.pkl`.

### 6. Start the server
```bash
python main.py
```
Server starts at **http://localhost:8000**

### 7. View the interactive API docs
Open **http://localhost:8000/docs** in your browser (Swagger UI).

## API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/apply` | Submit loan application, get eligibility result |
| GET | `/api/application/{id}` | Retrieve application details |
| GET | `/api/stats` | Aggregate approval statistics |
| GET | `/api/stats/applications` | Last 10 applications (anonymised) |
| POST | `/api/contact` | Submit contact form message |
| POST | `/api/score` | Quick ML score without saving |
| DELETE | `/api/application/{id}` | Erase personal data (DPDP Act) |
| POST | `/api/aa/initiate` | Account Aggregator: create a consent request |
| POST | `/api/aa/approve` | Account Aggregator: approve the consent (mock flow) |
| GET | `/api/aa/accounts/{session_id}` | Account Aggregator: linked bank account(s) |
| GET | `/api/aa/status/{session_id}` | Account Aggregator: poll consent/data status |
| GET | `/api/aa/fetch/{session_id}` | Account Aggregator: fetch parsed financial fields |
| GET | `/api/aa/data/{session_id}` | Account Aggregator: fetch balance + transaction detail |

### Account Aggregator (Setu/Finvu) — simulated, architecture-complete

The eligibility form's "Share Bank Data via Account Aggregator" option is
**currently a simulated/mock AA flow** — not "coming soon". The real Setu AA
sandbox requires registered business KYC (GST / incorporation documents) that
isn't available to an individual/student developer, so `routes/account_aggregator.py`
ships a mock layer that reproduces the full consent → bank-linking → data-fetch
flow with realistic synthetic data, using the exact same routes, request/response
shapes, and downstream feature schema the real integration would use. The
original Setu implementation is preserved (commented, inactive) in the same
file and can be re-enabled with `USE_MOCK_AA=false` in `.env` plus valid Setu
credentials — no rewrite required once business KYC is available. In short:
**production-ready pending business KYC**, working end-to-end today as a demo.

## Notes

- The SQLite database file (`graamcredit.db`) is created automatically on first startup.
- `model.pkl` must be generated before starting the server (`python ml/train.py`).
- For Gmail SMTP, use an **App Password** (not your main password): Google Account → Security → 2-Step Verification → App passwords.
- The admin panel is at `admin.html` in the frontend folder (direct URL, not in nav).
- All endpoints return standard HTTP status codes: `201` (created), `400` (validation), `404` (not found), `500` (server error).
- The DELETE endpoint soft-deletes: it anonymises personal fields but retains score/eligible data for aggregate statistics (DPDP Act compliance).
